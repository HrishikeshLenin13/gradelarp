# Gradelarp — direct HAC sign-in and source gradebook

## User flow

Open [Gradelarp](http://localhost:3000/). First-time visitors see a short introduction and one HAC login form. Select Leander ISD or Round Rock ISD, or choose **Another HAC district** and paste its official HTTPS HAC address. Enter credentials in the app, then choose **Sign in & sync**.

The server reads that portal’s current login form, preserves its anti-forgery cookie/token, POSTs credentials to the same portal, and fetches/validates its gradebook. A successful response automatically opens the school-reported gradebook and saves those academic records in a separate student profile. There is no mock connection, fixture selector, preview/import confirmation, seeded course data, or third-party hosted grade API in the user flow.

**Compatible HAC portals, not every ISD:** the generic adapter supports standard HAC username/password forms and recognized assignment tables. A district using another SIS, SSO, MFA, an interactive challenge, guardian student-selection workflow, or a changed gradebook layout needs its corresponding adapter. These states produce explicit errors, not a fabricated successful sync. Public login-form compatibility does not verify authenticated gradebook compatibility.

## Source accuracy

School-reported averages and original assignment marks are displayed directly from validated HAC markup. Missing/ungraded/exempt/unknown marks are retained; unknown marks are not converted to zero. Original due-date text is preserved rather than assigning an invented date/year. Extra-credit scores are not clamped to the manual calculator’s limits.

Visible assignment reconstruction is not substituted for HAC’s average: unpublished work and district policies can affect the school result. Unknown course credits, level, GPA policy, semester mappings, and grading semantics are not invented. The existing manual what-if/GPA tools remain available in manual profiles with explicitly entered policies. Source-only HAC profiles explain the missing prerequisites instead of inventing a GPA or prediction.

Within the same source period, partial sync keeps unavailable course/assignment records from the previous successful sync, marks the result partial, and explains which listed records may be stale. A failed login/parser/network request does not replace saved grades or claim success. Repeated successful sync updates the same portal/student profile instead of duplicating it. Genuine manual courses, tasks, scenarios, settings and other profiles remain unchanged.

## Connection and credential handling

- Credentials enter only a same-origin, strict-schema JSON POST body. GET/query-string secrets, cross-origin calls, non-JSON and oversized bodies are rejected. Browser password fields clear at submit; the password is not added to IndexedDB, localStorage, backups, session objects or logs.
- The connector fetches the selected portal’s real form before sending credentials. It requires the expected HAC credential fields, POST method, anti-forgery field, and same-origin HAC login action. Database/hidden fields come from that form, not hardcoded Katy flags or Database=10. Multi-database portals require an explicit valid choice.
- The public hosted HomeAccessCenter API is never called. Custom URLs are explicit user-confirmed destinations; arbitrary external login form actions are rejected before credential submission.
- HTTPS only, valid certificates, no nonstandard ports, no IP-literal portals, no URL userinfo/secrets, public-address DNS validation, and per-request DNS pinning retain the original Host/SNI/certificate hostname. Private/reserved/mapped/internal targets are rejected. All redirects remain on the selected HTTPS origin and HAC path. Credential POST bodies are never replayed through 307/308 redirects.
- Each connection has its own in-memory RFC6265 cookie jar. Only an opaque random app-session ID reaches the browser cookie (HttpOnly, SameSite=Strict, `/api/hac`, Secure on HTTPS). Loopback HTTP development is the explicit non-Secure-cookie exception.
- Sessions have a 30-minute lease; expiry/revocation is enforced server-side and reflected by the UI. A restart loses server sessions, not saved academic records. Disconnect destroys the Gradelarp-side school cookie jar; it does not change the school account or delete local grades.
- Requests have timeout, redirect, body/page-size, connection-count and retry limits. Errors are sanitized and responses are private/no-store. No raw source HTML, credential-bearing form values, school cookies or session tokens are logged by these modules.
- This is a local, single-process connector, not a production identity service. Public deployment still requires explicit request, provider/consent requirements, trusted ingress/rate-limit configuration, infrastructure log/body redaction, shared session design if scaled, retention/deletion review, and real authorized integration/security testing.

## Connection diagnostics follow-up (2026-10-15)

The reported generic error was reproduced with an unresolved public hostname: `ENOTFOUND` escaped the transport as a raw Node error and became HTTP 500. This is a confirmed cause of that message, not proof that it caused the user's account-specific attempt. The connector now classifies DNS, timeout, network, TLS, schema and unexpected runtime failures without exposing raw error messages or source records. Error details include the failing step (`login-page`, `sign-in`, `gradebook`, `student-identity`, `parse-records`, or `refresh`). Typed errors survive Next dev module re-evaluation. DNS abort listeners are removed when lookup settles, and socket timeouts remain timeouts rather than generic network errors.

The **Check district connection** button accepts only a portal URL, GETs its public form, validates the current same-origin action/CSRF field and discards its cookie jar. It never accepts credentials or asserts account authentication. Probe requests have a separate retry limit. Sign-in failures show a copyable code/step; credentials remain cleared after a sign-in attempt.

The running Next route reached both preset district forms. A separate real transport check sent EMPTY account fields with each form's current CSRF cookie/token: both returned HTTP 200 with the login form still present. No account credentials or authenticated academic pages were requested. Current authenticated account sync, district-specific gradebook markup and the user's original failure cause still require a private in-app retry and its displayed connection details. Evidence: `artifacts/hac-login-fix-2026-10-15/VERIFICATION.txt`.

## Source-record schema follow-up (2026-10-15)

A SOURCE_VALIDATION / parse-records failure occurs after the connection has fetched a gradebook and attempted to normalize it; it is not a generic network failure. Confirmed old-schema regressions include relative category weights above 100 and source assignment text beyond the manual-label limit. Category weights are now finite nonnegative source weights, not presumed percentages. Optional `weightText` / `percentText` preserve the original separate fields; `possibleText` preserves point notation and zero-point extra-credit denominators. New optional fields remain backward compatible with older saved source profiles. Display-label limits are source-specific; names are never truncated to fit a manual-entry field.

The adapter prioritizes explicit student-name/overall-average elements and assignment anchors. The field-only schema diagnostic is displayed on failures. In local development, only the last code/stage/schema-field names are saved under `.next/hac-validation-diagnostic.json`; production writes no diagnostic file. School values, account identifiers, credentials, cookie contents and HTML are excluded. Successful validated sync replaces diagnostic metadata with SYNC_OK / complete.
